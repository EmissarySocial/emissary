# middleware — Notes for AI Agents

Emissary-specific echo middleware; see [README.md](README.md) for the one-line inventory. The functions here are policy pieces — WHERE and in what order they run is decided entirely in [../server.go](../server.go) (`makeStandardRoutes` for the live server, `makeSetupRoutes` for the setup console), so ordering changes belong there, not here.

- **`CrossOriginProtection` is the only CSRF defense — for both server modes.** It wraps stdlib `http.NewCrossOriginProtection`, which inspects `Sec-Fetch-Site`/`Origin`: browser cross-site state changes are refused, while safe methods and header-less server-to-server requests (ActivityPub inboxes, Stripe webhooks) pass untouched — which is why federation does not need an exemption list. On the live server it backstops the SameSite=Lax cookie policy; on the setup console, which has NO authentication, it is the only thing preventing a malicious web page from posting configuration changes to localhost. Never remove it from either mode.
- **[csrf.go](csrf.go) does not contain the CSRF protection.** It holds `AllowCSR`, the opposite concern: a meta-refresh helper that lets SameSite cookies attach to a specific cross-site GET (the browser re-requests the same URL, now same-site, flagged by `__AllowCSR__`). It is wired to exactly one route — the OAuth client callback — and is safe only on idempotent GETs; the actual protection lives in [crossOriginProtection.go](crossOriginProtection.go).
- **`HttpsRedirect` must stay registered with `e.Pre`, before routing.** It exempts any host matching `uri.IsLocalHostname` (local and private-network deployments serve plain HTTP by design), and its HSTS header is `max-age` only — `includeSubDomains` and `preload` are hard to reverse on a multi-domain, often-proxied server, so they are a deliberate operator choice, not a missing default.
- **`Localhost` matches exactly the hostname `localhost` — keep it that strict.** Not any local domain, not a private IP, and it reads `Request.Host` rather than any forwarded header. It gates the unauthenticated setup console; loosening the match exposes config writes to anything that can name-resolve to the machine.
- **The live server's middleware order is a contract.** `Pre`: Recover → Digital Dome WAF → `HttpsRedirect` → RemoveTrailingSlash; `Use`: CORS (GET-only, no credentials) → `CrossOriginProtection`. The global `steranko.Middleware` is deliberately commented out — authentication happens per-route in the handler wrappers (see [../handler/AGENTS.md](../handler/AGENTS.md)), so nothing in this package may assume an authenticated context.
- **`CacheControl` and `MimeType` are wired to no route.** They are kept as ready-made helpers (fixed Cache-Control stamp; forcing the Accept header to reroute content negotiation) — finding zero call sites is expected, not a cleanup opportunity.
