# Default Notifications

The signed-in user's notifications section at `/@me/notifications`, split into four pages: Messages & Replies, Shares, Likes, and New Followers. [template.hjson](template.hjson) declares `templateRole: user-notifications` on the `Notifications` model (which operates on the User record), and the template is loaded directly by templateId in `build/builder_user_notifications.go` — unlike inbox/outbox templates, it is not user-selectable. All actions require `roles: ["self"]`, and the template extends `base-social`.

Each section has a page action (`replies`, `shares`, `likes`, `followers`) that bakes its notification type into the request with `set-query-param` (MENTION, ANNOUNCE, LIKE, FOLLOW) before rendering its page — [replies.html](replies.html), [shares.html](shares.html), etc. — so the shared [sidebar.html](sidebar.html) and [header.html](header.html) fragments and the `.Notifications` query all read the right section; the `index` action renders the replies page directly for the bare URL. Each page lazy-loads a matching `*-list` action ([replies-list.html](replies-list.html) and siblings) for infinite scroll, and each page opens an SSE connection to `/@me/sse/notifications` that re-fetches the header and list live when new notifications arrive.

The `read` action (the "Mark All Read" button) runs `mark-notifications-read` scoped by `?type=`, then fires `refreshSidebar` and `refreshPage` to clear counts and per-row unread dots; the `badge` action renders [badge.html](badge.html), the red-dot fragment the theme's navigation bar swaps in over SSE. On mobile the sidebar is hidden and [menu.html](menu.html) tabs render inside the header instead. Styles live in [stylesheet/](stylesheet/), served as `/.templates/user-notifications/stylesheet`.
