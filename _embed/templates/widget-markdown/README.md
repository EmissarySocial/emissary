# Markdown

This widget (widgetId `markdown`) embeds Markdown content into a stream, the authored counterpart to [widget-html](../widget-html)'s raw-markup escape hatch. Editors write Markdown in a plain textarea; readers see rendered, sanitized HTML.

Conversion happens when the containing Stream is saved, not when the page is rendered, so live pages never pay for parsing. [widget.hjson](widget.hjson) declares a `saveSteps` pipeline — an ordinary list of build steps, exactly like a Template action — that runs against this Widget whenever its Stream is saved: `{do:"set-data", values:{"data.html":"{{.Data.markdown | markdown}}"}}`. The `markdown` template function is the application's single converter (`tools/markdown`), which runs Goldmark and then the standard bluemonday sanitizer, so the stored `html` value is already safe. [widget.html](widget.html) then just prints it with `{{.Widget.Data.html | html}}`, doing no work at render time.

The pieces here are all general, not markdown-specific: any widget may declare a `saveSteps` pipeline to derive stored values from its own data, addressing its properties as `data.{property}` (the Widget's schema is nested under `data` to match the shape of a StreamWidget, and it still validates every write — an undeclared property is rejected). Both schema properties deliberately opt out of rosetta's guarded formats with `unsafe-any`, and each says why in a comment. The source cannot use `markdown`, because that format rejects any raw HTML tag outright and authors legitimately embed video here; the derived output cannot use `html`, because it was already sanitized by the application's policy and rosetta's stricter policy would silently delete those same embeds. Naming a format is not optional either — an unrecognized or absent format falls back to `no-html`, which strips tags and collapses whitespace, quietly destroying Markdown line structure on save.
