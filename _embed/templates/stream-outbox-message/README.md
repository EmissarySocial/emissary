# Post

An outbox message (`templateId: outbox-message`, `templateRole: outbox-message`, `socialRole: Note`) is a social post in a user's ActivityPub outbox — the Emissary equivalent of a Mastodon status. Its `containedBy: ["outbox"]` is special: rather than naming another stream template's role, it marks the template as creatable in a user's outbox (checked by `CanBeContainedBy("outbox")` in `service/stream_.go`), and the composer itself is launched from the `user-outbox` template's `outbox-add` action, which renders [create.html](create.html) inline. The `create` pipeline in [template.hjson](template.hjson) shows the full publishing path: `edit-content` collects the text as Markdown, which renders to sanitized HTML with bare URLs linked, photos are uploaded and a thumbnail set, then `save-and-publish` with `outbox: true` federates the post as an ActivityPub Note to followers, followed by `search-index`. Hashtags are extracted from `content.html` (`tagPaths`).

The template extends `base-social` (like/reply buttons for signed-in local users) and `base-intent` (modal flows that let anonymous fediverse visitors like, share, or reply via their own home server), so most social interaction UI is inherited. A note's own URL opens it as a modal (`view` includes `modal`), drawn with `as-modal` in its `medium` size (800px, from theme-global's `03-widgets-modal.css`) over its owner's profile at `/@{owner}?tab=notes`, with the note's own `<head>` ([head.html](head.html)) and `/{id}` in the address bar. A theme with a Notes tab reads `?tab=notes` to open it, and any other theme ignores it and draws the profile. A visitor who cannot see the profile gets the `page` action, [view.html](view.html), behind the modal instead. The modal ([modal.html](modal.html)) and the page share [note.html](note.html): author, in-reply-to context, attachments, and a responses footer; the `responses-replies`/`responses-likes`/`responses-announces` actions render the tabbed counts in the matching HTML files, [replies.html](replies.html) draws the first page of replies, and [reply.html](reply.html) draws one, both through the shared row [reply-row.html](reply-row.html) (including the rule-hidden placeholder for blocked content) and [reply-script.html](reply-script.html)'s `goToUrl`. `edit` reopens the composer in a modal and republishes; `delete` sends an unpublish (Delete activity) through the outbox before removing the stream. A richer inline `reply` action exists in the hjson but is currently commented out — local replies are instead created as [stream-outbox-reply](../stream-outbox-reply) streams from the `user-inbox` template.

## Additional Information

### The create pipeline, step by step

(1) `edit-content` ([step_EditContent.go](../../../build/step_EditContent.go)) renders [create.html](create.html) on GET, a plain textarea named `content`, and on POST stores it as Markdown (`format: MARKDOWN`), enforcing a rune-count limit and, via `require-content: true`, rejecting empty posts. Markdown renders to sanitized HTML and links bare URLs itself (goldmark's `Linkify`), so the pipeline has no `process-content` step: its `add-links` regex would wrap the URL inside a Markdown link's own `href`. Hashtag extraction happens in `Stream.Save`, driven by the template's `tagPaths`/`tagUrl`. (3) `save` persists the stream so it has an ID for attachments to hang off. (4) `upload-attachments` stores up to 10 photos (`image/*`), as the editor does. (5) `set-thumbnail` ([step_SetThumbnail.go](../../../build/step_SetThumbnail.go)) scans the attachments for the first image and writes its URL (`{Permalink}/attachments/{id}`) into the `iconUrl` schema property, or empty string if there are none. (6) `save-and-publish` with `outbox: true` ([step_SaveAndPublish.go](../../../build/step_SaveAndPublish.go)) first runs `CalcContext` and `AddReply` (recording this stream in a local parent's Replies collection when it is itself a reply), then `Stream.Publish` ([stream_publish.go](../../../service/stream_publish.go)) stamps the publish date and author, saves, and — because `outbox` is true — renders the stream as JSON-LD, saves that object into the shared ActivityStream cache, wraps it in a `Create` activity (`Update` when republishing), and delivers it through the user's ActivityPub Outbox to all followers, cc'ing the replied-to author so replies reach them even without a follow; webhooks and syndication targets fire from the same call. (7) `search-index` adds the post to the local search collection. Note the pipeline publishes with `state: "default"` — for outbox messages, "published" is a matter of PublishDate and fan-out, not the state machine.

### Inherited social UI and intents

Extending `base-social` ([base-social](../base-social)) brings in the `like-button`, `reply-button`, and `btn-social-outline` actions plus their partials, all inherited as named HTML templates through the `extends` merge; that is also where the `hidden-placeholder` partial used by [reply-row.html](reply-row.html) is defined. These fragments identify their target document via a `url` query parameter (falling back to the builder's Permalink), which is why the `view` action starts with `set-query-param` to seed `?url={Permalink}` before rendering. Extending `base-intent` ([base-intent](../base-intent)) adds the `intent` modal action, which lets an anonymous fediverse visitor on the permalink page hand the like/share/reply off to their own home server instead of authenticating here. In [note-actions.html](note-actions.html), Reply, Like, and Share each have a twin that runs the intent in one click, as the visitor's saved account; CamperJS shows a twin in place of its modal button only when that account supports its intent, so Like can be one click while Share still opens the modal. Share is an Announce of the Note itself, as on Qwertylicious items, and no longer writes a new post with the Note's title and link. Reply shows only while the Note accepts replies, and a visitor signed in here gets their own inbox's reply form and the local Like button instead. The bar is drawn on all three responses tabs, leading the row with the tabs at its right, drawn as pills (`[role=tablist].pills`), as under a Qwertylicious photo, episode, or place. The "..." button opens the account manager (`/{StreamID}/intent` with no intent), and the server sends it hidden, for CamperJS to show once an account is saved (`camper-show-if-has-accounts`).

### Responses, replies, and the rule-hidden placeholder

Reaction data is split between local collections and the ActivityStream cache: `ReplyLinksAfter`, `LikeLinksAfter`, and `ShareLinksAfter` ([builder_stream.go](../../../build/builder_stream.go)) page through the stream's LOCAL Replies/Likes/Announces collections of `CollectionItem` links (URI plus published date), which the responses tabs ([responses-replies.html](responses-replies.html), [responses-likes.html](responses-likes.html), [responses-announces.html](responses-announces.html)) and [replies.html](replies.html) iterate; each row then resolves its URI to a full remote document through `Common.ActivityStream` ([builder_common.go](../../../build/builder_common.go)), so [replies.html](replies.html) draws each of its first 12 replies in the same request, through [reply-row.html](reply-row.html). Until 2026-10-29 it drew an empty 100px placeholder per reply and loaded each one separately, so the list opened too tall and shrank as each reply arrived. Drawn together, one author whose server cannot be loaded must not abort the list, so the row loads the author through `.ActivityStream`, never `AttributedTo.Load`. There is no next page yet: a Note shows its first 12 replies. `Common.ActivityStream` loads through the viewer-specific client stack whose rules layer stamps the viewer's verdict (blocks, mutes, labels) into `document.Metadata.Labels`; when `Metadata.IsRuleHidden` is true, [reply-row.html](reply-row.html) renders the inherited `hidden-placeholder` partial as a click-to-reveal button that refetches the same row with `&reveal=true`, which `Common.ActivityStream` translates into a reveal option that lifts only the refusal — the verdict labels stay stamped, and the flag grants nothing to viewers with different rules. Finally, the commented-out `reply` action at the bottom of [template.hjson](template.hjson) sketches an inline composer that would `add-stream` an `outbox-reply` into the viewer's outbox with `inReplyTo` preset and retarget `#responses`; it is dormant, the live equivalent being the `user-inbox` template's `reply` action, while this template's active `reply` action only renders a single reply row.
