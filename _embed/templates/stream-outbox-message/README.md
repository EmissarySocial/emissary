# Post

An outbox message (`templateId: outbox-message`, `templateRole: outbox-message`, `socialRole: Note`) is a social post in a user's ActivityPub outbox — the Emissary equivalent of a Mastodon status. Its `containedBy: ["outbox"]` is special: rather than naming another stream template's role, it marks the template as creatable in a user's outbox (checked by `CanBeContainedBy("outbox")` in `service/stream_.go`), and the composer itself is launched from the `user-outbox` template's `outbox-add` action, which renders [create.html](create.html) inline. The `create` pipeline in [template.hjson](template.hjson) shows the full publishing path: `edit-content` collects the HTML, `process-content` strips disallowed HTML and auto-links text, attachments are uploaded (images/video/audio/PDF) and a thumbnail set, then `save-and-publish` with `outbox: true` federates the post as an ActivityPub Note to followers, followed by `search-index`. Hashtags are extracted from `content.html` (`tagPaths`).

The template extends `base-social` (like/reply buttons for signed-in local users) and `base-intent` (modal flows that let anonymous fediverse visitors like, share, or reply via their own home server), so most social interaction UI is inherited. [view.html](view.html) is the public permalink page, showing author, in-reply-to context, attachments, and a responses footer; the `responses-replies`/`responses-likes`/`responses-announces` actions render the tabbed counts in the matching HTML files, [replies.html](replies.html) pages through reply links, and [reply.html](reply.html) renders one remote reply from the ActivityStream cache (including the rule-hidden placeholder for blocked content). `edit` reopens the composer in a modal and republishes; `delete` sends an unpublish (Delete activity) through the outbox before removing the stream. A richer inline `reply` action exists in the hjson but is currently commented out — local replies are instead created as [stream-outbox-reply](../stream-outbox-reply) streams from the `user-inbox` template.

## Additional Information

### The create pipeline, step by step

(1) `edit-content` ([step_EditContent.go](../../../build/step_EditContent.go)) renders [create.html](create.html) on GET — a contenteditable composer whose htmx `configRequest` hook copies the div's innerHTML into a `content` form field — and on POST writes that HTML into `stream.Content`, enforcing a rune-count limit and, via `require-content: true`, rejecting empty posts. (2) `process-content` ([step_ProcessContent.go](../../../build/step_ProcessContent.go)) with `remove-html: true` strips anchor tags from the HTML (`html.RemoveAnchors`) and with `add-links: true` re-linkifies bare URLs (`contentService.ApplyLinks`); note that hashtag extraction does NOT happen here — `Stream.Save` does it automatically, driven by the template's `tagPaths`/`tagUrl`. (3) `save` persists the stream so it has an ID for attachments to hang off. (4) `upload-attachments` stores up to 10 files matching `image/*,video/*,audio/*,application/pdf`. (5) `set-thumbnail` ([step_SetThumbnail.go](../../../build/step_SetThumbnail.go)) scans the attachments for the first image and writes its URL (`{Permalink}/attachments/{id}`) into the `iconUrl` schema property, or empty string if there are none. (6) `save-and-publish` with `outbox: true` ([step_SaveAndPublish.go](../../../build/step_SaveAndPublish.go)) first runs `CalcContext` and `AddReply` (recording this stream in a local parent's Replies collection when it is itself a reply), then `Stream.Publish` ([stream_publish.go](../../../service/stream_publish.go)) stamps the publish date and author, saves, and — because `outbox` is true — renders the stream as JSON-LD, saves that object into the shared ActivityStream cache, wraps it in a `Create` activity (`Update` when republishing), and delivers it through the user's ActivityPub Outbox to all followers, cc'ing the replied-to author so replies reach them even without a follow; webhooks and syndication targets fire from the same call. (7) `search-index` adds the post to the local search collection. Note the pipeline publishes with `state: "default"` — for outbox messages, "published" is a matter of PublishDate and fan-out, not the state machine.

### Inherited social UI and intents

Extending `base-social` ([base-social](../base-social)) brings in the `like-button`, `reply-button`, and `btn-social-outline` actions plus their partials, all inherited as named HTML templates through the `extends` merge; that is also where the `hidden-placeholder` partial used by [reply.html](reply.html) is defined. These fragments identify their target document via a `url` query parameter (falling back to the builder's Permalink), which is why the `view` action starts with `set-query-param` to seed `?url={Permalink}` before rendering. Extending `base-intent` ([base-intent](../base-intent)) adds the `intent` and `follow-email*` modal actions, which let an anonymous fediverse visitor on the permalink page hand the like/share/reply off to their own home server instead of authenticating here.

### Responses, replies, and the rule-hidden placeholder

Reaction data is split between local collections and the ActivityStream cache: `ReplyLinksAfter`, `LikeLinksAfter`, and `ShareLinksAfter` ([builder_stream.go](../../../build/builder_stream.go)) page through the stream's LOCAL Replies/Likes/Announces collections of `CollectionItem` links (URI plus published date), which the responses tabs ([responses-replies.html](responses-replies.html), [responses-likes.html](responses-likes.html), [responses-announces.html](responses-announces.html)) and [replies.html](replies.html) iterate; each row then resolves its URI to a full remote document through `Common.ActivityStream` ([builder_common.go](../../../build/builder_common.go)), so [replies.html](replies.html) emits per-reply placeholder divs that htmx lazy-loads from `/{StreamID}/reply?id={uri}` and [reply.html](reply.html) renders the cached document. `Common.ActivityStream` loads through the viewer-specific client stack whose rules layer stamps the viewer's verdict (blocks, mutes, labels) into `document.Metadata.Labels`; when `Metadata.IsRuleHidden` is true, [reply.html](reply.html) renders the inherited `hidden-placeholder` partial as a click-to-reveal button that refetches the same row with `&reveal=true`, which `Common.ActivityStream` translates into a reveal option that lifts only the refusal — the verdict labels stay stamped, and the flag grants nothing to viewers with different rules. Finally, the commented-out `reply` action at the bottom of [template.hjson](template.hjson) sketches an inline composer that would `add-stream` an `outbox-reply` into the viewer's outbox with `inReplyTo` preset and retarget `#responses`; it is dormant, the live equivalent being the `user-inbox` template's `reply` action, while this template's active `reply` action only renders a single reply row.
