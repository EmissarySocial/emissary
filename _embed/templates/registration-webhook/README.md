# WebHook Registration

Signup flow (registrationId: `register-webhook`) that delegates registration entirely to an external service (a storefront, membership system, etc.), which then pushes account data back to Emissary over authenticated webhooks. [registration.hjson](registration.hjson) defines the admin config: the external `signup_url`, an optional `portal_url` where members manage their subscription, and a required shared `secret` that authenticates incoming webhook calls.

There is almost no UI here by design. The `view` action is a single `redirect-to` step that bounces `/register` visitors to the configured `signup_url`, and `confirm` renders [confirm.html](confirm.html), which is just the literal text `SUCCESS` — a machine-readable acknowledgment for the calling service rather than a page for humans. The external service creates and updates accounts by POSTing registration transactions to `/register/update`, where the handler (`handler/registration.go`) checks the transaction against the shared secret before calling `service.Registration.UpdateRegistration`; `allowedFields` (displayName, emailAddress, username, inboxTemplate, outboxTemplate, addGroups) controls which pushed fields are applied to the User, and notably excludes password, since authentication remains the external service's job.
