# Emissary Minimal

A stripped-back site theme for personal websites: the same page chrome every stream and user template renders inside, with the navigation reduced to a single centered bar and the signed-in user's own links tucked into a floating corner group. [theme.hjson](theme.hjson) declares `themeId: minimal` with `extends: ["global"]`, so this folder only supplies the visible skin — the shared design system (layout/typography CSS, javascript, hyperscript behaviors, htmx and icon resources) comes from [../theme-global/README.md](../theme-global/README.md) and is served under `/.themes/global/...`. The hjson also carries the admin-facing setup form, the `startupTasks` checklist shown to new domain owners, and the `startupStreams`/`startupGroups`/`defaultFolders` seed data used when a domain is first configured.

[page.html](page.html) is the outer skeleton: it renders [includes-head.html](includes-head.html) (meta tags, robots noindex, stylesheet links) and [includes-foot.html](includes-foot.html) (htmx, sse extension, hyperscript, bundled scripts), sets body-level htmx defaults (`hx-target="main"`, view transitions, push-url), and injects the active builder's output via `.GetContent`. [navigation.html](navigation.html) emits four independent pieces. The first is the skip link, emitted before everything else. The second is the `<nav>` bar across the top: the Startup Checklist link while the domain is in the STARTUP state, the top-level `.Navigation` streams otherwise, and Sign In/Join Now for visitors who are neither signed in nor a guest identity. The third is `.nav-menu`, the mobile layout described below. The fourth is `.floating-menu`, a card pinned to the bottom-right and rendered *outside* `<nav>`, holding the signed-in user's own links — Profile, Inbox, Conversations, Notifications with a live SSE-driven unread badge, and Server admin for owners — or a single Profile link for a guest identity.

## Mobile Navigation

Below 640px the `<nav>` bar is `display:none` and every site navigation link is reached through a control fixed to the top-right corner of the screen, which opens a full-screen sheet. Above 640px the bar is exactly what it has always been and the mobile markup is switched off entirely. Four properties of that markup are load-bearing, and each is pinned by a test in [../../../service/theme_minimal_navigation_test.go](../../../service/theme_minimal_navigation_test.go):

- **`class="framed"` stays on the bar's wrapper `<div>`.** It is not a nav class — it is the shared page-width class from [stylesheet/02-page.css](stylesheet/02-page.css) that also frames `user-outbox/*` and the setup console — but inside `<nav>` it is *also* what supplies the bar's flex layout, its centering at ≥640px, and its 1100px frame at ≥1024px. Nothing may restyle it for mobile; the bar is hidden by hiding `<nav>`.
- **The bar and the sheet are separate elements rendering the same links twice.** The sheet's copies carry **no `id`** and **not** the `nav-item` class, because [SelectNav](../theme-global/hyperscript/selectNav._hs) resolves the current section with `getElementById` (first match, not the visible one) and then sweeps `.nav-item` clean. The sheet's current-section mark is rendered server-side from `.NavigationID` instead.
- **The disclosure is a checkbox, and `role="button"` goes on the checkbox, never the `<label>`.** `:checked` is a selector, so a media query can switch the whole mechanism off above 640px; a `<details>` keeps its open state in a DOM attribute that no media query can reach. The role must stay on the input because the htmx `a11y` extension makes anything with it focusable — on a `<label>`, that turns one control into two tab stops.
- **The skip link sits outside both layouts.** `<nav>` is `display:none` on mobile and the sheet is `display:none` while closed, so a skip link inside either one stops existing for exactly the visitors it serves.

The control is `position: fixed` and nothing in the page reserves space for it, so it floats over page content and carries an opaque backdrop of its own to stay legible over an image. It is the close button as well as the open button, swapping its glyph on `:checked`.

## Navigation Settings

The theme's settings form has a **Header** tab whose toggles are stored on the Domain record under `themeData`, alongside the custom stylesheet, and read back in the templates through `.ThemeData`:

- **Top-Level Navigation** (`showNavigation`) — switch it off and the whole `<nav>` bar goes, Sign In block, Startup Checklist and the mobile menu included. The floating card of signed-in links is *not* affected, so a user who hides the bar keeps their own links.
- **Sign In Link** (`showSignup`) — switch it off and guests see neither the Sign In link nor the Join Now button, while the rest of the bar stays.

Both flags declare `default:true` in the schema, and that one declaration is what makes them visible-by-default in a Domain that has never saved them — the form's toggle widget and `.ThemeData` both fall back to it. [../../../service/AGENTS.md](../../../service/AGENTS.md) explains why it is required rather than decorative, and [../../../service/theme_minimal_navigation_test.go](../../../service/theme_minimal_navigation_test.go) pins it down.

To extend the theme, edit these HTML files or the four CSS files in [stylesheet/](stylesheet/), which are concatenated by the `bundles.stylesheet` entry and served as `/.themes/minimal/stylesheet`. [content/](content/) holds the seed documents referenced by `startupStreams` (home.json for the EditorJS welcome page, markdown for the others), and [resources/startup/](resources/startup/) holds the images and splash page used during first-run setup. Field semantics (extends, bundles, startup data) are interpreted by `model/theme.go` and `service/theme.go`.
