# Follower Activity Email

Notifies an email-method Follower that the account or stream they subscribe to has published new content. When an activity is published through the Outbox, `Outbox.sendNotification_Email` (service/outbox_publish.go) calls `DomainEmail.SendFollowerActivity` (service/domainEmail.go), which sends one message per email Follower with the subject "New Activity From {{.Name}}" and a `List-Unsubscribe` header populated from the Follower's unsubscribe link.

This is the only shipped email that declares a `headers:` block, and until `applyHeaders` was added to `ServerEmail.Send` those templates were parsed and then discarded, so the header had never actually been sent.

The unsubscribe URL reaches the template in two forms, because its two consumers need different ones: the body renders `{{.Unsubscribe}}` bare inside an `href`, while the `List-Unsubscribe` header needs it inside the angle brackets RFC 2369 requires. `Follower.UnsubscribeLinkWithBrackets` (model/follower.go) supplies the second, derived from `UnsubscribeLink` so the two can never disagree about the URL itself.

Both forms are always populated. `UnsubscribeLink` builds a URL for every Follower rather than returning `""` for non-email methods, because the URL is public and can be typed by hand — withholding the string would have looked like an authorization check without being one. The real gate is `Follower.LoadBySecret` (service/follower_.go), which queries `method == EMAIL` alongside the ID and then compares the secret, so a non-email record cannot be reached through `follower-unsubscribe` or `follower-confirm` at all. That is what lets `List-Unsubscribe-Post` be an unconditional literal here: `List-Unsubscribe` is never absent from this message, so one-click never announces an address that was not sent. `TestFollowerActivity_ListUnsubscribe` and `TestFollowerActivity_OneClickRequiresLink` (service/serverEmail_test.go) pin the pairing; `TestFollowerLoadBySecret_RejectsOtherMethods` (service/follower_test.go) pins the gate.

[email.hjson](email.hjson) declares the `follower-activity` emailId, the `Follower` model guard, and the to/subject/header templates; [body.html](body.html) is a Go html/template rendered by `ServerEmail.Send` (service/serverEmail.go) with the shared funcMap (it uses `htmlMinimal` to sanitize activity content). The data map provides `Name`, `Email`, `FollowerID`, `Secret`, `ParentLink`, `Unsubscribe`, `UnsubscribeWithBrackets`, `Activity` (the raw activity map, from which the body pulls `.Activity.object`), plus `Domain_Owner`, `Domain_URL`, `Domain_Name`, and `Domain_Icon`; note that the body also references `.URL` and `.Actor`, which `SendFollowerActivity` does not currently supply, so those spots render empty (the body is `html/template`, which renders a missing key as `""`; the to/subject/header templates are `text/template`, which renders it as the literal `<no value>`).
