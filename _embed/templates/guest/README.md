# Guest Profile Page

Profile/settings template (model: Identity, category: Special) for Guests — visitors who bought paid content through checkout or follow someone by email, and therefore have an Identity record but not a full User account. It is loaded by name in `build/builder_identity.go`, which requires `templateRole: guest` from [template.hjson](template.hjson), and it backs the `/@guest` routes in `server.go` (handler.GetIdentity / handler.PostIdentity). `containedBy` is empty because this template is never placed in the Stream hierarchy.

Every action is restricted to the `self` role (the signed-in guest). `view` renders [view.html](view.html), a settings-style page that shows the guest's name and identifiers, lists their privileges (purchases), and nags until a Fediverse username is connected; when the viewer is also a full authenticated User it shows the shared user-settings sidebar. `edit` is a small generated-form modal for the guest's name, while `email` and `webfinger` open modals ([email.html](email.html), [webfinger.html](webfinger.html) dispatching to [webfinger-add.html](webfinger-add.html) or [webfinger-edit.html](webfinger-edit.html)) that post an EMAIL or WEBFINGER identifier to `/@guest/identifier`; changing an identifier re-links the purchases made under it, which is why both edit screens warn about losing access to old purchases. `confirm` ([confirm.html](confirm.html)) is the "check your inbox" modal shown after a verification message is sent, since guests authenticate by emailed magic link (`/@guest/signin`) rather than a password.
