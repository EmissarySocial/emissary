# Default Outbox

The user's public profile page at `/@:userId` (or `/@me`): the outbox in ActivityPub terms, showing who the user is and what they have posted. [template.hjson](template.hjson) declares `templateRole: user-outbox` on the `Outbox` model (which operates on the User record), extends `base-social` and `base-intent` (the follow/like/reply intent actions offered to visitors from other servers), and is the one template in this batch with anonymous-facing actions: `view`, the `*-list` feeds, `sidebar`, `follow`, and `feed` all allow `roles: ["anonymous"]`, while editing actions require `self`.

The `view` action renders [outbox.html](outbox.html): an h-card/h-feed page with RSS and ActivityPub discovery links, tabs for Posts ([outbox-list.html](outbox-list.html)), Replies, and Likes, and — for the owner — an inline composer wired to the `outbox-add` action, which uses `add-stream` to create an `outbox-message` stream in the user's outbox. [sidebar.html](sidebar.html) shows the avatar, copyable `@user@host` handle, bio, and either Edit Profile/Sign Out buttons (self) or a Follow button that opens the intent flow (visitors). Profile editing is split across the `edit` modal (name, message, location, isPublic), `icon-edit`/`icon-delete` (avatar upload via `upload-attachments`), `links`/`links-table` (rel-me profile links), and `edit-template`, which lets the user pick any template with the `user-inbox`/`user-outbox` roles.

Two less obvious pieces: the `follower-confirm` and `follower-unsubscribe` actions are the landing pages for email-follower confirmation and unsubscribe links, and the `wizard-1` action plus the `WIZARD-STEP-1` state implement first-run onboarding — a new user chooses name, username, email, and password ([wizard-step-1.html](wizard-step-1.html)), then the pipeline sets the state to `LIVE`, saves, and runs `set-password`. The `feed` action serves the machine-readable outbox via `view-feed` (RSS/Atom/JSON, linked from the page head).
