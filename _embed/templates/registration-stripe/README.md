# Stripe Registration

Paid signup flow (registrationId: `register-stripe`) where new members subscribe through Stripe instead of filling in a local form. [registration.hjson](registration.hjson) defines the admin config form — Stripe publishable key, restricted key, webhook secret, pricing-table ID, and customer-portal URL, each validated by regex/URI formats — stored as the domain's RegistrationData.

The `view` action renders [view.html](view.html) as a standalone full page that embeds Stripe's hosted `<stripe-pricing-table>` web component using the configured publishable key and pricing-table ID, so checkout happens entirely on Stripe. Account creation is driven by Stripe webhooks rather than the `/register` form pipeline: `handler/stripe/signup.go` (`PostSignupWebhook`, routed at `POST /.stripe-connect/webhook/signup`) verifies the `Stripe-Signature` header against `stripe_webhook_secret`, then uses `stripe_restricted_key` to fetch customer details and create or update the corresponding User. The `stripe_portal_url` gives existing subscribers a link to manage billing in Stripe's customer portal.

## Additional Information

The real registration logic lives in [handler/stripe/signup.go](../../../handler/stripe/signup.go), reached at `POST /.stripe-connect/webhook/signup` ([server.go](../../../server.go)) through the `WithDomain` middleware. The sequence a developer can follow through `PostSignupWebhook` and `finishWebhook`:

1. Guard clauses: the domain must have a registration form configured (`domain.HasRegistrationForm`), and `stripe_webhook_secret` and `stripe_restricted_key` must both exist in the domain's RegistrationData, or the request fails.
2. The raw request body is read and its `Stripe-Signature` header verified with `webhook.ConstructEvent` against `stripe_webhook_secret`; only events whose type starts with `customer.product.` proceed — anything else is trace-logged and acknowledged with 200.
3. `finishWebhook` errors are `derp.Report`ed rather than returned, so once the signature verifies Stripe always receives `200 OK`; failures show up in Emissary's logs, not as webhook retries.
4. `finishWebhook` unmarshals the event payload as a Stripe Subscription, takes the first line item's Price (`getSubscriptionPrice`), and then fetches the full Product from the Stripe API using `stripe_restricted_key` (`loadStripeProduct`), because the webhook payload does not include the Product metadata that drives the next steps.
5. If the subscription status is `active` or `trialing`: `loadOrCreateUser` looks up the User by the Stripe customer ID stored in `User.MapIDs` (`model.UserMapIDStripe`); on a miss it fetches the Customer from the Stripe API and seeds a new User from it (DisplayName from the customer's name, falling back to description; EmailAddress; the customer-ID MapID). Then `addGroups` reads the Product metadata key `add_groups` (comma-separated group tokens, each resolved with `Group.LoadByToken`) and adds those memberships, `removeGroups` does the inverse for the `remove_groups` key, and `setPublic` sets `User.IsPublic = true` only when metadata `set_public` is `"true"`.
6. For any other subscription status (canceled, past due, etc.): `loadUser` only — if no matching User exists there is nothing to revoke and the handler exits quietly; otherwise `removeGroups` is applied to the `add_groups` list (undoing exactly what activation granted) and `setPublic` flips `IsPublic` back to false under the same metadata gate.
7. Finally `userService.Save` persists the User with the comment "Created by Stripe Webhook".

Practically, this means group access is configured on the Stripe side: each Stripe Product carries metadata (`add_groups`, `remove_groups`, `set_public`) naming the Emissary groups a subscription grants or revokes, and the webhook is the single writer that keeps Users in sync with their subscriptions. Note the flow never touches the `/register` form pipeline used by the other registration templates — the visitor's only local page is the pricing table in [view.html](view.html), and everything after that is Stripe checkout plus this webhook.
