# Navigation List

This widget (widgetId `navigation-list`) displays a hierarchical site-navigation menu built from the current stream's position in the site map: its grandparents, parent, siblings, and children, each tier optionally shown in full or collapsed to a single entry. It is the standard sidebar navigation for content sections.

[widget.hjson](widget.hjson) defines an optional `title` plus four enum settings — `grandparents` ("All"/"Grandparent Only"), `parents` ("All"/"Parent Only"), `siblings` ("All"/"Self Only"), and `children` ("All") — where an empty value hides that tier entirely. [widget.html](widget.html) is the entry template: it dispatches to the first non-empty tier via `.Widget.Data.IsZeroValue`, and the sibling files [grandparents.html](grandparents.html), [parents.html](parents.html), [siblings.html](siblings.html), and [children.html](children.html) are named sub-templates (every .html file in a widget folder is parsed into one template set, so `{{template "parents" $root}}` works across files) that chain into each other, nesting the next tier with indented styling at the ancestor matching `.ParentID`, at the current stream within the sibling list, and so on down to children. Data comes from the Stream builder's `.Ancestors`/`.Siblings`/`.Children` query builders and `.Parent`/`.Grandparent` accessors; links use `hx-get` with the wrapper's `hx-target="main"`, `hx-swap="innerHTML"`, and `hx-push-url="true"` plus the `turboclick` class, so a new tier means adding a sub-template file and wiring it into this dispatch chain.

## Additional Information

### How dispatch works

[widget.html](widget.html) picks a single entry template by testing the four settings in fixed order — `grandparents`, then `parents`, then `siblings`, then `children` — with `.Widget.Data.IsZeroValue`, which (per rosetta's `mapof.Any`) is true when the key is absent or holds an empty string. The first non-empty setting wins and its sub-template is invoked with the whole widget context; if all four are empty the widget renders only its optional title. The same "first non-empty of the remaining tiers" test is then repeated inside each sub-template to decide what nests beneath it, which is what lets intermediate tiers be skipped: with `grandparents:"Grandparent Only"`, `parents:""`, and `siblings:"All"`, [grandparents.html](grandparents.html) skips straight past parents and nests [siblings.html](siblings.html) directly. With the schema defaults (`grandparents:"Grandparent Only"`, `parents:"Parent Only"`, `siblings:"All"`, `children:""`) a freshly saved widget enters at grandparents and renders three tiers deep.

### What each tier actually queries

Despite the name, the Stream builder's `Ancestors()` (build/builder_stream.go) does not return the full ancestor chain: it loads the current stream's parent and queries all streams sharing that parent's `parentId` — that is, the parent and its siblings, one complete peer generation. Each "All" mode therefore renders one generation's peer list, and the four tiers map cleanly onto the family tree: [grandparents.html](grandparents.html) in "All" mode builds `$parentBuilder := .Parent "view"` and lists `$parentBuilder.Ancestors.Slice` (the grandparent and the grandparent's siblings); [parents.html](parents.html) in "All" mode lists `.Ancestors.Slice` (the parent and the parent's siblings); [siblings.html](siblings.html) in "All" mode lists `.Siblings.Slice` (the current stream and its siblings); [children.html](children.html) lists `.Children.Slice`. Because each tier is a distinct generation, `"All"` on adjacent tiers never produces duplicate entries. The `"* Only"` modes collapse a tier to its single on-lineage member: "Grandparent Only" renders one link via the `.Grandparent "view"` builder guarded by `.HasGrandparent`, "Parent Only" one link via `.Parent "view"` guarded by `.HasParent`, and "Self Only" just the current stream's bold label.

### Tier nesting and the lineage match

In "All" mode each template must decide which one peer in its list sits on the current stream's lineage, because that is where the next tier nests. Each file matches by hex-string ID comparison ([`StreamSummary.StreamID()`](../../../model/streamSummary.go) and the builder's `ParentID()` both return hex strings): grandparents.html compares each `$ancestor.StreamID` against `$parentBuilder.ParentID` (the grandparent's ID), parents.html compares against `.ParentID` (the parent's ID), and siblings.html compares against `.StreamID` (the current stream itself). Off-lineage peers render as plain `ellipsis`-classed links; the matching peer renders its link (or, in siblings.html, bold non-link text marking the page you are on) followed immediately by the next tier inside an indented `<div style="padding-left:8px; font-size:0.9em;">`. In "* Only" modes there is no list to search, so the next tier nests unconditionally after the single item. One vestigial guard to know about: siblings.html wraps its children call in `{{if ne "Hidden" $configChildren}}`, but `"Hidden"` is not a value in the schema enum (`children` is `["All"]` with default `""`), so the condition is always true — children are actually hidden because children.html renders nothing unless the setting equals `"All"`.

### Recursion shape and termination

The four templates are not mutually recursive in the strict sense — the calls form a one-way cascade that only ever descends: grandparents may invoke parents, siblings, or children; parents may invoke siblings or children; siblings may invoke children; and [children.html](children.html) contains no `{{template}}` calls at all, so the chain terminates there with a maximum depth of four and no possibility of a cycle. Every nested `{{template "..." $root}}` call passes `$root`, the original `build.Widget` for the stream being viewed, so `.Ancestors`, `.Siblings`, `.Children`, `.ParentID`, and `.StreamID` inside nested templates always resolve relative to the current page, never to the node they visually nest under; the only place a different builder appears is grandparents "All", which needs `.Parent "view"` to reach one generation higher than `Ancestors()` can. That unguarded `.Parent "view"` call is also the widget's one sharp edge: on a top-level stream it returns an error, template execution aborts, and `Stream.Widgets()` (build/builder_stream.go) logs the failure via `derp.Report` and continues, leaving this widget's output truncated while the rest of the page renders normally.
