# Article (BASE TEMPLATE)

This is the abstract base for Emissary's article content types (`templateId: article-base`, `templateRole: article`, `socialRole: Article`, `model: Stream`). It defines everything the concrete editors share: the schema (token, label, summary, a `content` object with `format`/`raw`/`html`, and `data.tags` for hashtags), the `default`/`published` states, the `viewer`/`editor` roles, and the full action set — a draft-based editing workflow (`edit`, `editor`, `promote-draft`, `discard-draft` all run inside `with-draft` steps), `publish`/`unpublish`, `widgets`/`widget`, `children` (drag-sort child pages), `upload-image`, `sharing`, `properties`, and `add-child`. It declares no `containedBy` list of its own, so nothing can create an article-base stream directly; it exists only to be extended by [stream-article-editorjs](../stream-article-editorjs), [stream-article-html](../stream-article-html), and [stream-article-markdown](../stream-article-markdown).

Inheritance works through the `extends` field in [template.hjson](template.hjson): at startup, `service/template.go` (`calculateInheritance`) recursively merges each parent named in `extends` into the child via `model.Template.Inherit`, which copies in any schema properties, states, roles, actions, and HTML templates the child has not defined itself — the child always wins on conflicts. This template itself extends `base-widget-editor`, which supplies the `stylesheet` bundle plumbing and the LEFT/TOP/RIGHT/BOTTOM widget locations that [view.html](view.html) renders around the content. Variants typically override only the `create` and `editor` actions: [editor.html](editor.html) here is a deliberate placeholder ("EDITOR CONTENT GOES HERE") that each concrete template replaces with its own editing UI, while [view.html](view.html), [edit.html](edit.html) (the editor chrome with breadcrumbs and menu bar), [heading.html](heading.html), [children.html](children.html)/[children-sort.html](children-sort.html), and [widgets.html](widgets.html) are inherited unchanged.

## Additional Information

### Draft lifecycle

The `with-draft` step ([step_WithDraft.go](../../../build/step_WithDraft.go)) swaps the pipeline's Stream builder for a draft builder, so every substep reads and writes a StreamDraft instead of the live stream. Drafts are copy-on-first-access: `StreamDraft.Load` ([streamDraft.go](../../../service/streamDraft.go)) looks for a draft with the same `_id` in the drafts collection, and when none exists it copies the live stream in and returns that copy. Because `edit`, `editor`, `widgets`, `widget`, `properties`, `upload-image`, and `discard-draft` all run inside `with-draft`, an author can edit content, rearrange widgets, and upload images without touching the published page.

`promote-draft` makes the draft live: [step_PromoteDraft.go](../../../build/step_PromoteDraft.go) calls `StreamDraft.Promote`, which copies the draft's URL, token, label, summary, icon, widgets, content, data, attribution, and inReplyTo onto the live stream, sets the requested state, saves, and deletes the draft; the action then runs `save-and-publish` (state `published`, `outbox: "false"`), `search-index`, and forwards to the live page. `discard-draft` is simply a `delete` executed inside `with-draft`, so only the draft record is removed and the live article is untouched. `publish` and `unpublish` operate on the live stream directly: `save-and-publish` ([step_SaveAndPublish.go](../../../build/step_SaveAndPublish.go) calling `Stream.Publish` in [stream_publish.go](../../../service/stream_publish.go)) stamps the publish date, sets the author and state, saves, and fires webhooks and syndication, while `outbox: "false"` skips the ActivityPub fan-out to followers; `unpublish` ([step_UnPublish.go](../../../build/step_UnPublish.go)) removes the page from the search index and resets the state to `default`. The `delete` action is the one place that passes `outbox: "true"`, so federated Undo activities are sent to any followers before the stream is removed.

### What variants override, and what they must not

Inheritance is a child-wins merge with no partial merging: `Template.Inherit` in [model/template.go](../../../model/template.go) copies a parent action only when the child has no action of that name, so overriding an action replaces its entire step pipeline. Children inherit the schema properties, states, roles, actions, widget locations, `templateRole`/`socialRole`/`model`/`tagUrl`, and every parsed HTML file the child does not define itself — a child HTML file with the same name as a parent's shadows it completely. Two things do not flow through: `tagPaths` deliberately never inherits (external template packages depend on that, per the comment in `model/template.go`), which is why each variant re-declares `tagPaths: ["data.tags"]`, and `containedBy` only fills in when the child leaves it empty, which is how the variants declare their own placement while this base stays uncreatable.

Variants are expected to override exactly two actions — `create` (to seed `content.format` and starter `content.raw`) and `editor` (to point `edit-content` at their own `editor.html` with the matching format) — plus supply the `editor.html` file itself. The splice point is the last line of [edit.html](edit.html), `{{template "editor" . }}`, which renders the variant's `editor.html` inside the base editing chrome; in exchange, every `editor.html` must define a `saveDraft(promote)` function (hyperscript or JavaScript) because the chrome's Promote button and menu bar call it — the convention, implemented by all three variants, is to POST the content to `/{StreamID}/editor`, optionally POST to `/{StreamID}/promote-draft`, then navigate to `/{StreamID}`. The remaining actions (`edit`, `widgets`, `children`, `properties`, `promote-draft`, `discard-draft`, `publish`, `unpublish`, `delete`) should be left alone: the base HTML files link to them by name and the draft workflow depends on their exact step sequences, and any `editor` override must keep the `with-draft` wrapper or content edits will save straight to the live stream.
