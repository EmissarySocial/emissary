# Reply

An outbox reply (`templateId: outbox-reply`, `templateRole: outbox-reply`, `socialRole: Note`) is a reply to another post, stored in the replying user's own ActivityPub outbox (`containedBy: ["outbox"]`, the special user-outbox location). It extends `outbox-message` ([stream-outbox-message](../stream-outbox-message)), inheriting its view, responses, and delete behavior, and adds one schema property: `inReplyTo`, the URL of the post being answered — which is what turns the published Note into a threaded reply when `save-and-publish` with `outbox: true` federates it.

Per [template.hjson](template.hjson), it overrides only `create` and `edit`: `create` is open to any `authenticated` user and renders [create.html](create.html), a lightweight contenteditable composer that posts its HTML through `edit-content`/`process-content` and publishes immediately (no attachments, unlike the parent). It is not created from its own page — the `user-inbox` template's `reply` action runs `add-stream` with `roles: "outbox-reply"`, `location: "outbox"`, and `with-data: {inReplyTo: "{{.Permalink}}"}` to spawn one inline while browsing the newsfeed. It declares only a `default` state (inheritance still copies the parent's `published` state in, but the create/edit pipelines publish with `state: "default"`), since replies are federated in the same step that creates them.
