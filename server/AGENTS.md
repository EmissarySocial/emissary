# server — Notes for AI Agents

This package holds the root `Factory` (and its setup-mode sibling `SetupFactory`): the server-level services, plus one `service.Factory` per hosted domain. [README.md](README.md) explains the `wiring` generation-swap model, reload semantics, the compare-and-swap save split, and the live-config certificate types — read it first. The rules below are the finer-grained traps.

- **New mutable state goes in the `wiring` struct, not on `factoryCore`.** If a reload writes it and a request reads it, a plain struct field is a data race; put it in `wiring` and publish through `rewireLocked`. [wiring_test.go](wiring_test.go) is the `-race` harness that enforces this.
- **The `Locked` suffix is the reentrancy discipline.** `reloadLock` is a plain `sync.Mutex`, not reentrant: methods ending in `Locked` assume the caller holds it, unsuffixed ones take it. Calling an unsuffixed method from inside a `Locked` context self-deadlocks — which is why `SetupFactory.UpdateConfig` calls `updateConfigLocked`, never `UpdateConfig`.
- **Never hand the common database or queue to a domain factory.** `refreshDomain` deliberately omits them from the `service.NewFactory` call: domain factories read `Queue()` and `CommonDatabase()` through the server factory on every use, so a reload can never strand them on a disconnected client or a stopped queue. Any new server-level resource a reload can replace must follow the same read-through pattern.
- **A queue is stopped at most once, and only when it is actually being replaced.** `turbine.Queue.Stop` panics on a second call, and any task already handed to a stopped queue dies silently ("Turbine Queue: stopped"). The unchanged-guards in `refreshQueue` (`queueReady`, `queueWithStorage`, `queueDatabase` compared by pointer identity) are what makes the single Stop safe — do not simplify them away. The pointer comparison also relies on `readConfig` refreshing the common database BEFORE the queue; keep that order.
- **Compare connection settings as scalar strings, never as the config's maps.** The unchanged-guard in `refreshCommonDatabase` compares `commonDatabaseURI`/`commonDatabaseName`, plain strings snapshotted at connect time, because setup-console handlers mutate the config's `mapof.String` values in place — an old-map-vs-new-map comparison can never detect a change.
- **The setup console's queue is always in-memory.** `SetupFactory.configure` calls `refreshQueue(false)` so the console can never consume production tasks; keep it that way.
- **`SetupFactory` must drain its config subscription.** The channel holds a single slot, so an un-drained subscription wedges the storage watcher permanently and freezes the console's view of the configuration — whose next save then writes that stale snapshot over other nodes' changes. Its own saves echo back through the change stream, which is why the unchanged-guards must stay cheap.
- **`factoryCore.init` populates in place, and must keep doing so.** The services it builds capture method values and field pointers bound to that exact address (`factory.ClientIP`, `&factory.contentService`, ...); refactoring it to build-and-return a value would dangle them all.
- **derp reporters are replaced with ONE `derp.SetPlugins` swap, and the list never publishes empty.** `refreshDerpPlugins` builds its list locally: a Clear-then-Add sequence races every concurrent `derp.Report` and opens a window with no reporters at all, precisely when reload errors fire. A config declaring no valid loggers still gets a console reporter, because the server must never run without an error sink.
- **`CertificateCache.Get` returns `autocert.ErrCacheMiss` UNWRAPPED, and `CertificateHosts` delegates matching to `autocert.HostWhitelist`.** autocert compares the miss error by identity to decide whether to request a certificate, and `HostWhitelist` applies the IDNA normalization matching the SNI name on the wire — wrapping the error or hand-rolling the hostname comparison silently stops issuance. Both types take a `ConfigProvider` because `autocert.Manager` is built once per process: anything captured by value at construction is frozen forever, while anything reached through a function or interface follows the live configuration.
- **Index sync runs only when the connection actually changed, and stays bounded.** Index definitions are a function of the binary, not the configuration, so re-syncing on every reload amplifies across the cluster (every save, every node); and `syncCommonDatabaseIndexes` runs under `reloadLock`, so its 60-second deadline is what keeps one sick server from pinning every configuration write. Related gotcha: `go f(g())` evaluates `g()` synchronously, so `go derp.Report(slowCall())` is not async — the slow call still blocks the caller.
- **A domain that fails to load is simply absent from the registry, and every request to it returns 421.** `refreshDomains` logs the failure with the hostname on the always-on zerolog channel; when debugging a mysterious "421 Hostname is invalid", check boot/reload logs for that domain before suspecting routing.
- **Deliberately frozen at boot — do not re-flag as propagation bugs:** `startHTTPS` (in the repo root's [server.go](../server.go), not this package) will not bind :443 when the boot configuration has zero non-local domains, so the first such domain still needs a restart; port changes are restart-required; and autocert reads the ACME contact email once, when it registers the account.
